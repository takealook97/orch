# Space tree

A compact Spaces sidebar shows machines, spaces and nested Git worktrees, then tabs and their panes. Pane names identify orch workers and the Head; a second line shows the actual model and effort when known.

![Space tree](preview.png)

**What you see:** A 30px Spaces header has expand-all, collapse-all and new-space controls. Machine and tab rows are 26px, spaces 30px, nested worktrees 28px and pane rows 36px. Each level indents 14px, with 12px disclosure arrows and dim branch guides. Space avatars share the app's palette assignments. Names use 12–12.5px text; pane details use 10.8px. All colors come from the current theme. Focused panes have a raised background and a 2px accent stripe. Spaces participating in a run show an accent orch pill; run tabs show mode and completed/total workers.

**How it behaves:** Working, blocked, done and idle use the corresponding theme color (idle uses dim); unknown statuses are dim. Machines and tabs initially open, the active space opens, other spaces start folded. Explicit fold choices persist. The header expands or collapses everything. Click selects a space, tab or pane; chevrons only fold. Double-click a name or press F2 on the highlighted row to edit it. Enter or blur commits; Escape cancels; an empty value restores the automatic name. Machine and terminal pane names are shared display aliases. Up/Down move the highlight, Left/Right fold/unfold and Enter selects. Right-click spaces and tabs opens their shipped menus. Machines and panes offer 이름 바꾸기; Pane actions opens the shipped pane menu. Drag spaces to reorder within the same machine. Machine + creates a space there; Connect repairs a replaced machine using the shipped reconnect flow. Hover highlights rows and buttons.

**Built from:** This mod occupies a layout block using `{"mod":"space-tree"}` with no required props. Its root is a vertical header and scrollable row list. `plumbing.js` retains shipped spaces Git checks, worktree ordering, folder watches, machine refresh, reconnect and space menu behavior. `model.js` is a pure projection; `rows.js` renders rows; `rename.js` owns a retained InputState. `tree-menu.js` supplies the alias popup through internal props `{treeMenu,kind,id,current,target}`. Live data comes from `machines`, `spaces`, `panes`, `terminals`, `shared` and `theme`. Actions use `space.select/new/move/rename`, `tab.select/rename`, `pane.focus`, and shipped `menu` overlays. It runs read-only Git checks and `/Users/deepeet/.local/bin/orch hud panes` every 3 seconds, retaining the last valid JSON. Local monitor/server/branch/plus/chevron SVGs are copied from workspace-chrome. Fold state lives in localStorage `tree.folded`; aliases use `space-tree.alias.machine.<name>` (local computer: `local`) and `space-tree.alias.pane.<terminal address>` shared keys.

**Watch out:** Terminal addresses and remote row IDs must stay whole, including `/`. Git's shared common directory determines nesting; the pure model receives the shipped computed order. Pane order follows the app's `panes()` array, which does not expose spatial layout order. Alias precedence is user alias, worker role/name, Head, main/program, then sub N/program (the second pane is sub 1). Pane detail precedence is worker model/effort, terminal argv model/effort, then program name, followed by live status. Mod panes without terminal addresses cannot receive terminal aliases. The shipped space/tab menu Rename still uses the app's native prompt; name double-click and F2 use this mod's inline editor. Alias popup edits remain within that popup. A failed hud poll dims orch labels and shows a warning without erasing data. Every minute it prunes dead fold keys and terminal aliases; offline machines retain their state. Active worktrees under a folded repository require opening that repository. No installation or layout switch is part of this source delivery. `preview.png` is reserved for an integrated runtime capture and is not supplied by the headless check.
