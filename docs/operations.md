# Local evidence, experiments and removal

No Head savings have been demonstrated. Existing ask/do logs do not cover Head or pane usage; do not infer historical missing values.

## Explicit measurement

`orch measure import < record.json` writes one versioned record to `~/.orch/measurements/records.jsonl` (or ORCH_HOME), with a file lock, fsync and duplicate/conflict checks. `orch measure report` groups by session, period, subject, phase, measured/estimate/missing and coverage. Each group retains entity, source and optional model identity, and shows n_total/n_with_value/n_missing (joint token-pair coverage), n_with_input/n_missing_input and n_with_output/n_missing_output (dimension coverage), plus observed duration subtotals and duration coverage; input/output subtotals independently include every observed dimension; observed subtotals are partial evidence, never a complete total when values are missing. Different sources or phases must not cover overlapping usage; IDs deduplicate the same observation, not arbitrary overlapping intervals. Use provider event IDs and nonoverlapping period identifiers. Do not import a cumulative session total alongside its component events as separate usage.

Example unavailable Head observation:

```json
{"version":1,"id":"session-1-contract","session":"session-1","period":"turn-1","subject":"head","entity":"head","phase":"contract","source":"manual","kind":"missing","coverage":"unavailable","input_tokens":null,"output_tokens":null,"duration_ms":null}
```

For actual provider evidence, use kind `measured`, source identifying the provider/export, null for unavailable counts, coverage `partial` or `complete`. Estimates use kind `estimate` and stay in separate groups. Zero means an observed zero. Supported subjects are head/pane/task; phases are contract/execution/review/rework/session. Manual import remains the provider-independent path. The opt-in local collector below supports specific Claude and Codex usage records without fabricated historical backfill. Session and period identities are required, even for missing usage. Coverage is reporter-declared and must match the evidence actually observed.

Optional event codes: new_defect, false_positive, accepted_fix, failure, recovery_started, recovered, recovery_failed. Reason codes: unknown, timeout, interrupted, exit, scope, persistence, capacity, policy, quota, validation, human_confirmed. accepted_fix/recovered/recovery_failed require `related` identifying an existing record in the same session. Give a finding and its fix/recheck distinct IDs. The record is a structured assertion; keep reproduction/proof and acceptance judgment in run findings/decisions, linked by ID. A worker finding alone is not a confirmed defect.

Completed ask/do/test attempts automatically record the CLI-reported tokens as partial execution coverage (or null when unavailable), duration and a failure reason code. Cache hits reuse prior task evidence and create no new token observation. Pane completions record missing usage and executor failure outcomes. Fallback records recovery_started before prompting, then recovered/recovery_failed when the replacement passes/fails the executor completion gate; this is executor recovery, not user acceptance. Confirmed defects, false positives, accepted fixes and human recovery judgments require explicit evidence import. Outside the Claude Stop hook described below, Head/pane usage requires an explicit operator-declared provider session binding; arbitrary transcript ownership is not discovered. Telemetry contains only identities, numeric values and fixed codes, with no prompt or freeform secret fields. Identifiers must not contain secrets. Malformed logs fail closed and are preserved for repair; import never resets them. Records remain local and uninstall preserves them.

## Local provider usage collection

```bash
orch measure collect --provider claude --session-file /absolute/session.jsonl \
  --session provider-session-id --subject head --entity declared-head \
  --period sample-1 --phase execution
# Use --subject pane --entity worker-name for a declared pane binding.
# Add --export to emit normalized records without storing them.
orch measure report
```

All seven binding flags are required. Session must agree with the provider identity inside the file; no directories are scanned and no model is called. Entity/subject/period/phase are operator-declared, not discovered ownership. Use isolated ORCH_HOME for experimental samples so they cannot overlap production task evidence. The export envelope's records array contains individual records compatible with manual import. A SHA-256 file-path fingerprint supplies local provenance without exposing the path. Moving the source retains observation identity.

Only identity/model/counter metadata is decoded into typed structs; content is never serialized or included in errors. Closed JSONL records have a 16 MiB limit. Malformed closed records, negative/overflowed counters, unsupported explicit schema_version, inconsistent identity or binding, and conflicting stored evidence reject the whole batch before writes. Claude's application version string is not a usage schema version. A final record without a newline is skipped and reported as unclosed_record. Unknown/no-usage formats return unavailable, with no invented zero-token row. Store I/O errors require normal log repair; validation atomicity is not a crash transaction.

Claude assistant usage rows require their own matching sessionId, including streaming rows. Stable provider-global message identities and request/message consistency prevent a copied observation from counting again under another session. Only nonempty stop_reason messages are final observations; incomplete streaming chunks are ignored, identical finalized observations deduplicate, and conflicting final counters/model/request identities reject the entire batch within or across imports. Identical cross-session copies retain the first observation and its original session/file provenance; the import summary reports duplicate_observations and duplicate_provenance=existing-observation-retained. Copies cannot rebind entity/subject/phase/period or change counters/request identity. These are synthetic copy semantics, not a claim about actual provider resume/fork formats. New collected records include message_id/request_id metadata; old session-scoped collector records without that metadata must be reconciled separately before mixing with the new collector, since their request identities cannot be recovered; a matching legacy session-scoped message digest fails closed before appending new observations. Manual import remains unchanged. New final messages append safely. Inclusive input is uncached input + cache creation + cache read, consistent with task usage; missing cache fields make inclusive input unknown. Output is independently nullable. Observed zero remains zero.

Codex token_count total_token_usage snapshots yield differences from the preceding distinct snapshot; the first snapshot is the observed session prefix. last_token_usage is never added. Identical snapshots are ignored. IDs depend on provider/session and distinct-snapshot order, remaining stable for append-only growth/replay. Decreasing cumulative counters reject the batch as a reset requiring explicit reconciliation; rewritten/reordered history can conflict. Missing dimensions remain unknown until two consecutive known snapshots establish a delta. Fully missing snapshots are retained as missing/unavailable intervals, and partially missing snapshots retain independently observed dimensions. For example (10,1) → (null,2) → (50,6) yields (10,1), (null,1), (null,4): observed input subtotal 10 with 1/3 input coverage, output 6 with 3/3 output coverage. The unallocated 40 input tokens are not bridged across the gap: phase/model ownership cannot be established for those intervals. A later (60,8) yields (10,2). Dimension coverage makes these losses explicit; no subtotal implies a complete session total. turn_context.model attributes each interval; absent model stays absent. Input already includes cached input; output includes reasoning output. Model changes do not reset cumulative accounting.

All collected usage has partial coverage: transcript observations do not establish complete billing, full Head activity, duration or savings. Rebinding an event to another entity/phase/period is rejected. Manual imports can overlap other sources; the operator must avoid that. Reported subtotals are not full-session cost.

Local smoke (2026-11-04): a declared Claude sample yielded 5 final observations, inclusive input 442332 and output 4285; a Codex sample yielded 11 cumulative intervals, input 510254 and output 9496. Separate usage-only source calculations matched both, and replay left isolated storage unchanged. No private session identity/path or content is committed. These samples do not prove current Head ownership or Head savings.

## Automatic Head collection

After rerunning `orch install`, the Claude Stop hook launches a detached `orch __measure-head` collector for the supplied session transcript. It reuses local provider collection with provider=claude, subject=head, entity=head, period=session ID and phase=`session` (whole-session observations). Workers never collect. Set `ORCH_AUTO_MEASURE=0` to opt out. Errors append timestamped, content-free lines to `~/.orch/measure.log` (or ORCH_HOME).

Coverage is partial: only finalized, newline-closed observations are collected; the final assistant message may still be unclosed when Stop fires and is collected only by a later Stop. This does not establish complete billing, Head activity, duration or savings. Replays deduplicate existing observations; avoid overlapping manual bindings.

Each fixture/repetition has both arms with alternating first-arm order and seeded pair shuffling. Odd repetition counts differ by one first-arm sample. Weighted cost is an assumption, not money or measured Head cost. All ask attempts bypass cache. Re-render interrupted experiments with `python3 eval/run.py report <directory>`; missing attempts stay missing. Inspect individual results for token estimates and provider evidence; no recommendation or savings claim follows from these proxies.

Duration workloads use increasing batches of parsing/algorithm implementation functions (3/15/45), single versus three pane workers with exclusive module names and isolated worktrees. ## Safe uninstall and reinstall

`orch uninstall --repo /path/to/orch` and `--dry-run` preview without writes. `--apply` backs up every changed existing file/link under ORCH_HOME/backups before applying the plan. New installs retain a versioned local ownership manifest with repository, exact binary and block identity. Legacy installs without a manifest use the current block and standard binary paths. Only the exact installed generated constitution block, exact hook commands for that repository's bin/orch or ~/.local/bin/orch, and links targeting that repository's skill/playbooks/bin/orch are owned. Mixed hook groups retain user commands and other events. Modified blocks, wrappers, foreign links, real directories and nonregular config files are preserved. Ambiguous markers, malformed JSON and malformed hook shapes fail before mutations. Repeated removal is harmless; state/history/measurements and backups remain. Empty constitution files may remain; whitespace outside owned markers is preserved. JSON formatting can change; historical matcher values and Codex `/hooks` trust cannot be reconstructed. Remove trust manually. Backups are not restored over later user changes.

Reinstall preflights links and configurations and refuses foreign links, real directories and malformed config rather than overwriting them. Configuration writes use temporary-file rename. Files are snapshot-checked before uninstall mutation, but simultaneous external config writers are not transactionally locked; stop them while applying. An apply I/O failure may leave a partial removal; backups and idempotent retry are the recovery path.

## Head execution guard boundary

The Head only plans/evaluates/instructs/reviews/judges/communicates. There is no tiny-task or takeover exception. Tests/builds and Git/install execution go through orch workers or orch test; read-only inspection is permitted.

PreToolUse applies the practical execution redirect in an orch-managed context: ORCH_RUN, an active run owned by the current Head in Herdr, or `ORCH_HEAD_GUARD=1` in Herdr. Outside Herdr an explicit ORCH_RUN enables the same redirect. Set ORCH_HEAD_GUARD=1 for a direct-mode Herdr Head without a run. Workers are exempt from this execution redirect and keep their existing no-delegation guard; unrelated ordinary sessions are unaffected. A finished run is no longer an implicit managed context. Policy still applies outside enforcement coverage.

Recognized edit/patch tools are denied except contracts/**, dag.yaml, acceptance.md, decisions.md and findings.md under the selected run, and goal.md in the current Head's newest draft goal. Frozen goal state and implementation files remain protected. Only exact known edit API names exclude their bodies from shell inspection; missing edit paths fail closed. Paths resolve symlinks. Known build/test/interpreter/package commands, mutating Git subcommands, common file operations and output redirections in recognized shell tools are redirected. Read-only cat/rg/git status/diff and orch orchestration pass. Quoted orch requirements/test commands are argument data, while shell substitutions, redirections and chained recognized execution remain inspected. ORCH_RAW_HERDR bypasses only the pane-creation redirect. The execution scanner handles quotes, escapes, separators, $() substitutions, nested shell -c scripts and descriptor redirects. Unknown Git globals/subcommands, dynamic command positions/programs, malformed quotes, process substitution, heredocs, grouping, eval and backticks require delegation. Known Git global options are parsed by arity; -c/--config-env always delegate because configuration can execute programs. Git --output and -O/--open-files-in-pager options delegate even on inspection subcommands. Ordinary --no-pager log/diff/status remain usable. Read-only Git forms also include shortlog/merge-base/name-rev/count-objects/diff-tree/diff-index/diff-files/cherry/range-diff/whatchanged/var/ls-remote, branch listing and ref filters, remote listing/show/get-url, stash list/show, tag listing, reflog show, worktree list, config list/get/get-all/get-regexp with scope/format flags, single-ref symbolic-ref reads, and submodule status; refusals name the first blocked command (up to 160 bytes of command text). Shell -c accepts literal programs and short-option c bundles; --norc/--noprofile are recognized separately and unknown long options delegate. builtin wrappers and attached sed -e/--expression= programs are inspected. Scoped planning apply_patch heredocs with quoted delimiters preserve path checks and chained commands; other heredocs delegate. Unknown tool names, shell aliases and opaque commands are not resolved comprehensively. Unlisted wrappers/binaries and language forms can escape this denylist (for example nice/timeout/noglob wrappers, trap, sort -o, truncate, tar extraction, gawk inplace and alternate sed address syntax); this is an explicit existing limit, not comprehensive write prevention. Separate legacy pane-creation and worker no-delegation matchers retain their stricter behavior. This is a workflow guard, not a security sandbox or proof that arbitrary execution is impossible. A user can alter environment/hook configuration; that changes enforcement, not policy.

Exact MCP filesystem names `mcp__filesystem__write_file` and `mcp__filesystem__edit_file` receive Head, active-goal scope and Codex goal-compilation path checks, including missing-path rejection. Path recognition does not grant a command-body exemption to MCP tools or terminal write APIs. The scanner emits literal argv once, then the policy checks common awk `system`, print/printf redirects and pipes, and sed `w`/`e` commands and substitution flags. Ordinary awk comparisons, grep patterns and Git log formats remain inspection data. Known Go module mutations/get, find deletion/exec actions and explicit shell script invocations are also redirected. These checks cover the listed forms rather than a complete parser for either language or shell.

Test `fakeCLI` fixtures place failing sentinels for `codex`, `claude`, `agy`, `gemini` and `cr` ahead of the real PATH. Explicit mocks override them, including multiple mocks for provider fallback tests; missing or misspelled mocks fail locally while system tooling remains available.

## Provider failures and recovery

A provider process exiting zero does not establish success: nonempty denied_actions or an empty response fail the task and prevent ask caching, including reuse of older denied-result caches. Inspect output.log and resolve the specific permission before retrying; orch does not change global permissions. Structured provider envelopes are never substituted for an empty answer. Failed writing tasks still capture changed paths for scope review, but skip final tests and completion commits.

`do` requires a Git repository to freeze a baseline and validate owned paths. Non-Git run directories are planning artifacts: the Head can edit the exact permitted planning files directly; use --cwd with a repository for implementation work.

A known interrupted inline DAG command is stopped and persisted pending before the resume instruction is printed. An uncertain launch or interrupted scheduler without confirmed child termination still requires inspection and state reconciliation. Knowledge merge failures propagate and are retryable after repairing knowledge.md; facts are deduplicated, and finished panes are closed before merge attempts. Worktrees with missing/corrupt task.json remain protected as unverified writers: inspect the recorded process/pane and restore task state from backup before retrying run end. No automatic timeout deletes unknown writers. Already closed runs stay closed.

Automatic measurement failures produce warnings and do not change task/test/pane execution results or prevent successful ask caching. Required execution state persistence remains fatal. Explicit measure import/report keeps rejecting malformed logs and conflicting records; preserve and repair the evidence file before retrying. Evidence n_total counts rows, including recovery events, rather than workers or execution attempts. Duration coverage and token coverage are separate; n_missing tracks unavailable token pairs even when another metric is measured. A catalog key used when ModelID is unavailable is a fallback identity, not a provider observation.

Uninstall removes a matching ownership manifest last, after backing it up and applying the owned changes, so a later installation can use another repository. Without a manifest, shared-bin hooks and the common constitution block are removed only when ~/.local/bin/orch points to the requested repository's bin/orch. Ambiguous legacy ownership is preserved. JSON cleanup retains large integer values and literal HTML characters, while whitespace and key order may change.
